# 牧童大卫 · 开发计划文档

> 本文件是游戏《牧童大卫》的开发计划（设计文档）。
> 第一章可玩 Demo 已实现（见仓库根目录 `index.html` 与 `js/`）。
> 本文档在 Demo 基础上规划后续核心系统，重点是 **35 位勇士（同伴）系统** 与 **先知（医治 / 驱魔）系统**。
>
> 注：旁注里的圣经出处仅作设定依据，方便对齐人物与事件，可按实际企划调整命名与数值。

---

## 0. 总览

大卫的一生贯穿三条主线，三种核心武器（已在 Demo 验证）也贯穿始终：

| 武器 | 用途 | 对象 | 设计含义 |
|---|---|---|---|
| 弹弓（投石索） | 远程攻击主力 | 物理敌人（野兽、巨人、敌兵） | 大卫的招牌，打歌利亚的关键 |
| 杖与杆 | 近战 · 护羊 | 物理敌人、贴身缠斗 | 牧人本职，保护羊群 |
| 弹琴赞美 | 驱邪 · 安抚 | 邪灵免疫物理，唯弹琴可驱散；对野兽起安抚 | 赞美神，驱赶恶魔（撒上 16:23） |

在此之上，本计划新增两大长期养成系统：

1. **勇士系统**：大卫一生中陆续招募的勇士（gibborim），通过各种剧情事件获得，组队并肩争战。**名册严格按圣经对齐**：以「撒母耳记下 23:8-39」为主（三勇士 + 三十勇士，“共三十七人”），并补以「历代志上 11:10-47」的平行名册及额外勇士。
2. **先知系统**：撒母耳、拿单、迦得等先知，提供 **膏立、预警、医治、驱魔** 等非战斗与辅助战斗能力。

## 1. 勇士系统（大卫的勇士 / gibborim）

### 1.1 设计定位

- 勇士是大卫的 **可招募同伴**，不是一次性 NPC。
- 每位勇士通过 **特定剧情事件 / 支线** 解锁（不是商店购买），强调「患难中结义」。
- 战斗中可带 **1 名队长 + 至多 3 名出战勇士**（共 4 人小队，含大卫则 5 人），其余在「勇士营」待命。
- 每位勇士有 **1 个招牌技能**（取材于其圣经事迹），以及成长属性。
- **人物忠于圣经**：撒下 23 明说「共三十七人」（三勇士 + 以亚比筛/比拿雅为首的三十勇士）；代上 11 的名册更长，末尾（11:41-47）另有若干不见于撒下的勇士。本作将**两处名册合并收录**，不需凑数；可招募勇士约 **50 位**（含历代志补录），具体上阵与图鉴收录可由策划划定。
- 约押（元帅）、亚比筛、比拿雅因地位特殊，另设为「核心三将」单独成线（见 1.5）。

### 1.2 招募方式（事件驱动）

招募统一走「事件 → 条件 → 入队」流程，便于扩展：

```
事件触发（到达地点 / 完成任务 / 战斗胜利 / 对白选择）
   → 满足条件（等级 / 持有物 / 前置勇士 / 章节进度）
   → 播放招募过场（该勇士的来历与誓言）
   → 加入「勇士营」，可编入小队
```

典型招募事件类型：
- **解围救援**：在某战斗事件中救下被围的勇士（如亚多兰陷阵），战后入队。
- **比武 / 立功**：完成勇士给出的考验（如比拿雅雪天坑中打狮子的回忆任务）。
- **共御外敌**：非利士人来袭，几位勇士一同死守麦田（沙玛守麦田，撒下 23:11-12），守住后入队。
- **忠义感召**：大卫逃亡基云时，亡命之徒陆续来投（撒上 22:1-2），形成早期勇士池。
- **取水明志**：三勇士闯非利士营为大卫取伯利恒井水（撒下 23:15-17），触发「三勇士」结义。

### 1.3 战斗中的勇士（并肩争战）

- 小队制：回合制战斗里，大卫与出战勇士 **各自行动一次**（按敏捷/速度排序出手）。
- 每位勇士有 **职业定位**：陷阵（前排高攻）、护卫（前排高防/护羊护人）、弓手（远程）、勇将（爆发斩杀）、副手（armor-bearer，可替队友挡伤/递弹药）。
- **羁绊**：特定勇士同时出战触发增益（如「三勇士同列」→ 全队暴击率提升）。
- **协战技**：大卫弹琴赞美时，在场勇士获得「士气」增益（呼应「赞美鼓舞军心」）。

### 1.5 核心三将（独立剧情线）

- **约押**：元帅型，统军；剧情中亦有争议（杀押尼珥、亚玛撒），可做「忠而难驭」的复杂角色。
- **亚比筛**：三十勇士之首，「举枪敌三百」（撒下 23:18），救大卫脱离非利士巨人（撒下 21:17）。
- **比拿雅**：勇力传奇——**雪天下到坑中打死狮子**、击杀两个摩押勇士、夺埃及巨人的枪反杀（撒下 23:20-21）；后为大卫侍卫长。其「坑中屠狮」可做成一段可玩回忆战，与第一章大卫打狮呼应。

## 2. 先知系统（医治 / 驱魔）

### 2.1 设计定位

先知不是普通战士，而是 **属灵支援单位**，承接 Demo 已确立的「属灵 vs 物理」主题（弹琴驱邪灵）。先知能力分两类：

- **非战斗（剧情/世界）**：膏立、预言指引、定罪与悔改、解锁路线。
- **战斗辅助（出战或后援）**：医治、解除诅咒、驱魔（对邪灵/受邪灵附身者特别有效）。

### 2.2 主要先知

| 先知 | 阶段 | 能力（设计） | 依据 |
|---|---|---|---|
| 撒母耳 | 早期 | 「膏立」：永久提升大卫成长；圣所庇护回血 | 膏大卫（撒上 16:13） |
| 拿单 | 王朝期 | 「指正」：解除「罪/心魔」debuff；预言指引支线 | 责大卫（撒下 12） |
| 迦得 | 逃亡—王朝 | 「先见预警」：战前预知敌方弱点/布阵 | 大卫的先见（撒下 24:11） |
| 亚比亚他（祭司） | 逃亡期 | 「以弗得求问」：战前占卜，提示最优技能 | 携以弗得来投（撒上 23:6-9） |

> 后世先知以利亚 / 以利沙（医治、复活、驱逐邪灵之事）不属大卫时代，仅作能力设计灵感来源，不入大卫主线名册。

### 2.3 医治与驱魔机制

- **医治（Heal / Cure）**
  - 单体/群体回复体力；进阶可「复元」解除中毒、流血、虚弱等状态。
  - 与大卫已有「祷告（回血）」区别：先知医治更强、可群疗、可解状态，但先知为稀有支援位，CD/次数受限。
- **驱魔（Exorcism / Dispel）**
  - 对 **邪灵 / 被附身者** 命中率与伤害大幅提升（与弹琴赞美形成「双驱邪手段」：弹琴是大卫自带，先知驱魔是支援强化）。
  - 可 **解除附身**：部分敌人是「被邪灵附身的人/兽」，驱魔后变为可对话/可救助对象（呼应「救人非灭人」）。
  - 对邪灵 BOSS：先知驱魔 + 大卫弹琴的 **合击** 触发额外效果（如「赞美与代祷」combo）。

### 2.4 与勇士系统的协同

- 先知 **不占出战格**，作为「后援位」每战提供 1 次支援（医治或驱魔），鼓励「勇士冲锋 + 先知托底」的配置。
- 邪灵类战斗中，纯物理勇士输出被压制（延续 Demo 机制），必须依赖大卫弹琴或先知驱魔，强化主题表达。

## 6. 数值系统（属性 + 公式）

### 6.1 主属性（四主属，暗黑3 式，主题化命名）

| 主属性 | 代号 | 作用 | 主题含义 |
|---|---|---|---|
| 力量 | STR | 提升物理伤害（弹弓/杖杆），决定重装备需求 | 牧人体魄 |
| 敏捷 | DEX | 命中、闪避、暴击率、攻击速度、护甲微量 | 投石索的精准 |
| 体力 | VIT | 最大生命 HP | 耐力 |
| 信心 | FAI（即 energy/法力位） | 提升「弹琴赞美/驱邪」伤害与体力上限 | 对耶和华的信靠（把魔法映射成赞美/信心，贴合主题） |

> 说明：用「信心 FAI」替代暗黑的「精力 Energy / 法力」，因大卫的「法术」即赞美与信靠神的能力。

### 6.2 派生属性公式

设主属性为 STR/DEX/VIT/FAI，装备加成为 `+x`：

```
最大生命   maxHp        = 20 + VIT*4 + 装备(+maxHp)
体力上限   maxStamina   = 50 + FAI*2
物理攻击   physMin/Max  = 武器基础(min/max) * (1 + STR*0.03) + 装备(+phys)
圣琴攻击   harpMin/Max  = 武器基础(min/max) * (1 + FAI*0.05) + 装备(+holy)
护甲       armor        = Σ装备护甲 + floor(DEX*0.25)
减伤率     reduction    = armor / (armor + 10 + 8*敌人等级)        // 暗黑式护甲曲线, 封顶 0.75
暴击率     crit         = 0.05 + DEX*0.002 + 装备(+crit)          // 封顶 0.50
暴击倍率   critMult     = 1.5 + 装备(+critDmg)
闪避率     dodge        = DEX*0.003 + 装备(+dodge)               // 封顶 0.30
攻击冷却   cd           = 武器cd * (1 - min(0.4, DEX*0.004))       // 攻速
```

### 6.3 伤害结算流程（每次命中）

1. **命中/闪避判定**：守方 roll < dodge → `MISS`（飘灰字「闪避」），结束。
2. **基础伤害**：`base = randInt(min,max)`（物理用 physMin/Max；弹琴用 harpMin/Max）。
3. **暴击判定**：roll < crit → `base *= critMult`，标记暴击（飘黄字 + 星形迸发）。
4. **词缀/元素加成**：叠加装备的 `+x% 伤害`、`+驱邪伤害` 等。
5. **减伤**：`dmg = max(1, floor(dmg*(1-reduction)))`。
6. **邪灵门控（保留核心设定）**：`type==='spirit'` 时，物理伤害**强制封顶为 1** 并弹「物理无效」提示；唯 `harp` 走全额公式。`type==='beast'` 时 harp 改为「安抚」（降攻 + 回血）。
7. **飘字**：命中处向上飘出伤害数字，按类型着色（白=普通物理，黄=暴击，紫金=驱邪，灰=闪避/抵抗）。

### 6.4 等级与经验

```
击败敌人      → 玩家获得 enemy.xp 经验
升级所需经验  xpToNext(L) = 20 + L*15
升级时        → 自由属性点 +3（或按职业自动分配），maxHp 回满，飘「LEVEL UP!」
```

敌人也有 `level`，影响其 HP/atk/掉落物品等级与玩家减伤曲线。

## 7. 装备系统（暗黑式：稀有度 / 词缀 / 物品等级 / 掉落）

### 7.1 装备槽位（5 槽，与三主动武器解耦）

> 三种武器（弹弓/杖杆/弹琴）是 **主动技能**（按 1/2/3 切换），不占装备槽。
> 装备槽提供**被动加成**与**特效**：

| 槽位 | id | 典型加成 |
|---|---|---|
| 武器焦点 | `focus` | 上好的投石索 / 橡木杖 / 金弦琴：+物理或+驱邪伤害、+暴击 |
| 护甲（身） | `armor` | +护甲、+最大生命 |
| 头盔 | `helm` | +护甲、+VIT |
| 护符 | `amulet` | +暴击、+暴伤、+全属性 |
| 戒指 | `ring` | +DEX/+FAI、+攻速、+生命偷取 |

### 7.2 稀有度（rarity）

| 稀有度 | 名称 | 颜色 | 词缀数 | 备注 |
|---|---|---|---|---|
| common | 普通 | 白 `#c8c8c8` | 0 | 仅基础值 |
| magic | 魔法 | 蓝 `#4a90ff` | 1–2 | |
| rare | 稀有 | 黄 `#ffd24a` | 3–4 | |
| unique | 暗金（传奇） | 橙金 `#ff8a3c` | 固定词缀 + 1 传奇特效 | 命名装备 |

（预留 `set` 套装绿色 `#46d369` 作后续扩展。）

### 7.3 物品等级与基础值

```
itemLevel  = clamp(来源等级 + randInt(-1,2), 1, 99)
reqLevel   = max(1, itemLevel-2)
基础护甲    baseArmor = floor(itemLevel * 1.5) (+槽位系数)
基础伤害加成 basePhys  = floor(itemLevel * 0.8)
词缀数值随 itemLevel 与稀有度线性缩放
```

### 7.4 词缀池（affix，前缀/后缀随机）

`+STR` `+DEX` `+VIT` `+FAI` `+最大生命` `+物理伤害%` `+护甲` `+暴击率` `+暴击伤害` `+攻速` `+生命偷取` `+驱邪伤害` `+经验获取` `+拾取范围`。
每条词缀有 `{stat, min, max}`，掉落时 `value = randInt(min,max)*稀有度系数*(itemLevel缩放)`。

### 7.5 掉落与拾取（loot）

- **掉落表**：`lion`（精英）必掉 1 件 `rare+`；`spirit`（首领）必掉 1 件 `unique`；游荡小怪按概率掉 `common/magic`。
- **地面表现**：掉落物落在敌人死亡点，头顶按稀有度画**颜色光柱**，名字浮动。
- **拾取**：走上去（距离 < 拾取范围）自动拾取 → 进背包；并做**自动装备最优**比较（按评分 `score=Σ加成权重`），更优则自动穿上并飘「已装备 · XXX」。
- **背包**：无限格（demo），可在装备面板手动切换。

### 7.6 装备面板（C 键，全部画在 canvas）

- 左：人物 5 槽位，物品名按稀有度着色，空槽显示「—」。
- 右：主属性（STR/DEX/VIT/FAI）+ 派生属性（maxHp/物攻/驱邪/护甲/暴击/闪避/攻速）+ 等级/经验条。
- 下：背包列表，键盘上下选择 + Enter 装备 / 触摸点击装备。

  itemLevel: number; reqLevel: number;

}

interface Equipment { focus: Item|null; armor: Item|null; helm: Item|null; amulet: Item|null; ring: Item|null; }

// 玩家（扩展）
interface Player {
  /* …位置/朝向/动画… */

}

// 敌人（扩展）
interface Enemy { /* …原字段… */ level: number; xp: number; lootTier: Rarity; }

// 飘字
interface Popup { x: number; y: number; text: string; color: string; life: number; vy: number; }

## 12. 总体架构（模块化引擎）

分两层，**逻辑引擎（engine-agnostic core）** 与 **表现层（Phaser 3 适配）** 严格解耦：

```
┌─────────────────────────── 表现层（Phaser 3） ───────────────────────────┐
│  BootScene / WorldScene / MapScene / BattleHUD / DialogueScene / MenuScene │

└───────────────────────────────────┬───────────────────────────────────────┘
                                     │  IEngineView（事件回调 / 渲染指令）
┌────────────────────────────────────┴──────────────────────────────────────┐
│                      逻辑引擎核心（纯 TS，可 node 单测）                       │
│  GameApp（编排/主循环 tick） ── 持有以下子引擎，单一职责、明确方法调用：         │
│   • MapEngine     地图引擎：瓦片/碰撞/可行走/出入口/触发器                      │
│   • WorldEngine   世界(关卡)引擎：地图节点图、解锁、切图、传送、探索进度          │
│   • MonsterEngine 怪物引擎：刷怪/AI/仇恨/分组/精英与首领                        │
│   • WeaponEngine  武器引擎：三主动武器 + 投射物 + 命中判定                      │
│   • EffectEngine  特效引擎：VFX 事件队列（拉弓/冲击波/音波/飘字/光柱…）          │
│   • StatsEngine   等级引擎：属性派生/伤害公式/经验升级（= Stats.ts）            │
│   • LootEngine    掉落引擎：稀有度/词缀/物品等级/掉落表（= Items.ts）           │
│   • HeroEngine    英雄(队伍)引擎：英雄卡/招募/出战/同伴 AI/各自升级             │
│   • QuestEngine   任务引擎：主线状态机 + 支线 + 事件触发                        │
│   • DialogueEngine对话引擎：对白队列/分支选择/旁白/过场                         │
│   • SaveEngine    存档引擎：序列化进度/背包/英雄/地图解锁（localStorage/JSON）   │
└─────────────────────────────────────────────────────────────────────────────┘
```

**约定（务必遵守，保证可复用 + 可测）：**
- 子引擎之间**不直接互调表现层**；需要画面反馈时，push 一个事件到 `EffectEngine` 或通过 `IEngineView` 回调（如 `view.spawnVfx(...)`、`view.playDialogue(...)`）。
- 每个子引擎是一个 class，构造期注入它依赖的其它引擎（依赖注入），**不使用全局单例**，便于单测替身（mock）。
- 所有可序列化运行时状态集中在 `GameState`，子引擎对其读写；`SaveEngine` 只认 `GameState`。
- 文件位置（建议）：`assets/scripts/engine/<XxxEngine>.ts`；数据 `assets/scripts/data/`（地图、英雄、敌人、事件、对白皆为纯数据）；Phaser 场景 `assets/scripts/scenes/`。

### 12.1 子引擎接口草案（TS）

```typescript
/** 主编排：每帧 tick 推进所有子引擎；对外暴露输入与查询。 */
export class GameApp {
  state: GameState;
  map: MapEngine; world: WorldEngine; monster: MonsterEngine;
  weapon: WeaponEngine; effect: EffectEngine; stats: StatsEngine;
  loot: LootEngine; hero: HeroEngine; quest: QuestEngine;
  dialogue: DialogueEngine; save: SaveEngine;
  constructor(view: IEngineView) { /* 注入并互相装配 */ }
  tick(dt: number): void;                 // 主循环：移动→AI→战斗→特效→任务检查
  input(cmd: InputCmd): void;             // 移动/攻击/换武器/交互/开面板
  enterMap(mapId: string, entry?: string): void; // 切图（世界引擎驱动）
}

/** 表现层只需实现这一组回调即可（Phaser/Canvas 皆可）。 */
export interface IEngineView {
  spawnVfx(e: VfxEvent): void;            // 特效引擎产出的瞬时表现
  popup(text: string, x: number, y: number, color: string): void;
  playDialogue(lines: DialogueLine[], onDone?: () => void): void;
  toast(msg: string, ms?: number): void;
  onMapChanged(mapId: string): void;      // 切图后表现层重建场景
  onPartyChanged(): void; onFinish(stats: FinishStats): void;
}

export interface MapEngine {
  load(def: MapDef): void;
  walkable(c: number, r: number): boolean;
  triggersAt(c: number, r: number): Trigger[]; // 出入口/事件触发器/宝箱
  exits(): MapExit[];                          // 通往其它地图的边界/门
}

export interface WorldEngine {
  graph: WorldGraph;                       // 地图节点 + 相邻边（互通）
  isUnlocked(mapId: string): boolean;
  unlock(mapId: string, reason: string): void;
  travel(toMapId: string, entry?: string): void; // 已解锁地图间传送/回访
  discovered(mapId: string): number;       // 探索完成度 0..1
}

export interface HeroEngine {
  roster: HeroCard[];                      // 已招募英雄卡
  recruit(heroId: string): void;           // 事件触发招募
  party: string[];                         // 出战名单（含大卫，至多 N 人）
  setParty(ids: string[]): void;
  grantXp(heroId: string, xp: number): void;
  updateCompanions(dt: number): void;      // 同伴在地图上的 AI 与攻击
}
```

## 14. 互通大世界 + 关卡解锁（暗黑式）

### 14.1 世界图谱（地图节点图）

```typescript
export interface WorldGraph { nodes: MapNode[]; edges: [string, string][]; }
export interface MapNode {
  id: string; name: string; biome: string; recommendLevel: number;
  unlockBy: 'start' | 'story' | 'explore'; // 初始可达 / 主线解锁 / 探索发现
  storyChapter?: number;                    // 属于哪一章（主线门控）
  exploreOnly?: boolean;                     // 纯探索区（刷怪/招募/宝箱）
}
```

- **互通**：已解锁的地图节点之间可经「出入口/世界地图」**自由回访**（像暗黑的镇子↔野外↔地牢），用于刷怪、补招募、找宝箱、练同伴。
- **解锁两种**：
  1. **主线门控**：随剧情章节推进，关卡一个个开放（`unlockBy:'story'`，`storyChapter`）。
  2. **探索发现**：在已开放地图找到隐藏出口/完成支线 → 解锁纯探索区（`unlockBy:'explore'`）。
- **探索进度**：每图记录已揭开区域 / 已清怪点 / 已拾宝箱（`WorldEngine.discovered`）。

### 14.2 关卡引擎职责
- 维护「当前地图 + 已解锁集合 + 各图探索进度」于 `GameState`。
- 提供 `travel()` 切图：保存离开图状态 → 加载目标 `MapDef` → 通知表现层重建场景（Phaser Scene 切换）→ 在指定入口落位。
- 与 `QuestEngine` 协作：主线推进时调用 `world.unlock(mapId,'story')`。

## 17. 引擎选型与迁移路线（待用户拍板）

**建议**：采用 **Phaser 3** 作为表现/场景框架（HTML5 网页游戏），**保留并复用现有引擎无关 TS 核心**（`Stats.ts`/`Items.ts` 等已 39/39 单测）作为逻辑引擎，按第 12 节拆分为模块化子引擎。

| 方案 | 优点 | 代价 |
|---|---|---|
| **A. Phaser 3 + TS 逻辑引擎（推荐）** | 场景/资源/补间/物理/输入开箱即用；多地图大世界用 Scene 管理省力；HTML5 发布成熟；逻辑核心仍可单测 | 一次性渲染层迁移（逻辑核心基本复用）；包体变大（用户已确认不在乎） |

**迁移步骤（方案 A）：**
1. 引入 Phaser 3（`npm i phaser`）+ esbuild 打包到 `web/`。
2. 把现有 `GameCore` 按第 12 节拆成子引擎（`engine/*.ts`），保持纯 TS、补单测。
3. 表现层用 Phaser 实现 `IEngineView`：`MapScene`（瓦片/角色/同伴/敌人/特效）、`DialogueScene`、`MenuScene`（英雄卡/装备/世界地图）。
4. 先迁移**第一章**作模板验证（玩法对齐现 Demo + 同伴 1 名 + 1 张探索区），再按第 15 节逐幕填充。

## A.3 进行中：暗黑式鼠标操作（细化规格）

落地到引擎无关核心（移动用「移动目标点」、瞄准用「鼠标朝向」），再经 Phaser 指针接入：
- **左键点地面**：设置移动目标点，角色寻路/直行朝该点奔跑；按住持续跟随光标。
- **左键点怪物**：将该怪设为攻击目标，自动靠近至武器射程/触及范围后攻击；目标死亡后停止。
- **攻击朝向 = 鼠标方向**：弹弓飞石射向光标；杖近战朝光标一侧挥击与判定；弹琴原地范围施放（不依赖朝向）。
- **并存**：鼠标操作与 WASD/方向键、J/空格 攻击共存，任一输入都可驱动；触屏虚拟摇杆保留。
- **数据**：核心新增「移动目标点 moveTarget / 攻击目标 attackTarget / 瞄准点 aim」；`update()` 据此推进移动与攻击；渲染层只需把鼠标坐标与点击事件转发进来。
